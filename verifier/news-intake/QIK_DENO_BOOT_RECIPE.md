# Targeted Deno boot qualification recipe

This is an inert source-only recipe, not a workflow or deployed function. Test only the actual candidate index.ts import, native Deno.serve listener/HTTP dispatch and dummy environment handling; no native SQL or earlier component suite is repeated. Provider fetch is intercepted with an explicit empty native-work response. Loopback HTTP stays inside one network-none disposable container; no host ports are published.

Runtime: official [Deno v2.9.7 Linux x64 release](https://github.com/denoland/deno/releases/tag/v2.9.7), asset deno-x86_64-unknown-linux-gnu.zip, 41,596,794 bytes, SHA256 c6527f24f4b16031d3ae4fa9f658d5f11534c8d84ce7dc8502420280919c3490 (official release asset metadata). Verify archive bytes and size before extraction. This version is an explicit portable-runtime qualification target; it is not asserted to equal hosted Supabase Edge Runtime.

Use the existing pinned Python base image python@sha256:519591d6871b7bc437060736b9f7456b8731f1499a57e22e6c285135ae657bf7, no build/install. Download/extract only in an operation-specific disposable remote runner directory. Mount the verified deno binary and source read-only; container user 65534, memory 256MiB, pids 32, no capabilities, no-new-privileges, read-only filesystem, network none, tmpfs /tmp 64MiB, DENO_DIR=/tmp/deno, DENO_NO_UPDATE_CHECK=1. No Docker socket or credential mounts.

Run deno run with --no-config --no-lock --no-npm --no-remote --cached-only --no-code-cache --no-prompt, --allow-read=/workspace, --allow-env restricted to the seven MIP_QIK_* names in index.ts, and --allow-net=0.0.0.0:8000,127.0.0.1:8000 for the container-local listener/test caller only. The fixture verifier/news-intake/qik_deno_boot.mjs supplies dummy values and preserves the real Deno.serve call, capturing its returned handle solely to shut it down. Require exact binary deno --version 2.9.7, source guard, a <=60-second command bound, <=120-second job bound, server shutdown and owner-labelled container cleanup. Remove only the operation-specific downloaded/extracted binary directory, after exact-path validation; no artifacts.

A PASS would qualify Deno 2.9.7 dependency import (including built-in node:crypto), actual index environment refusal/boot and actual local HTTP handler dispatch. It would not qualify hosted Edge version parity, gateway authentication, PostgREST/JWT/session handoff or provider behavior.

Exact-version flag names are checked against [Deno v2.9.7 CLI definitions](https://github.com/denoland/deno/blob/v2.9.7/libs/cli_parser/src/defs.rs); execute the verified binary's run --help before the test and refuse missing flags. Native shutdown/finished semantics are provided by [v2.9.7 HTTP implementation](https://github.com/denoland/deno/blob/v2.9.7/ext/http/00_serve.ts); the fixture awaits both, with the outer process/container timeout retaining cleanup authority if shutdown stalls.

Changed admission coverage: Deno may provide a non-null stream for a zero-byte POST. The host now inspects at most one chunk with a 250ms deadline, accepting EOF only and cancelling without waiting for peer cancellation. Focused Node coverage exercises EOF, data, stalled and errored streams; actual Deno covers implicit and explicit empty network POST. The existing 45s worker limit remains an admission cutoff, not operation cancellation. Server cleanup marker is inside finally after shutdown/finished, so it can prove cleanup even when assertions fail.

Deno body diagnosis: pinned 2.9.7 yielded one zero-byte chunk for both implicit and explicit empty HTTP POST. Admission now permits at most two reads under a single 250ms deadline: EOF directly, or one Uint8Array of length zero followed by mandatory EOF. Data, repeated zero chunks, errors and deadline expiry remain refused. This is not an exact allocation-byte ceiling. No request payload is accumulated or drained.
