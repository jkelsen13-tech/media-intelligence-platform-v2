# Comparison host and exact-claim recovery candidate

This source-only candidate connects the existing journal worker to a Supabase Edge handler. It is not deployed, registered, scheduled or credentialed. Existing source-comparison-run remains untouched. The native fixture runs this HTTP handler in fresh Node processes, with a mocked provider HTTP seam forwarding RPC calls to disposable PostgreSQL. It does not qualify Deno boot, Edge gateway/JWT validation, PostgREST schema exposure or hosted networking.

015 recovers only discovered original claim requests without a prepared terminal journal record. It reuses the native jobs, request_runs, lease_owners and journal. An unissued request replays exactly; an issued claim waits for its two-minute lease and existing 30/60-second backoff, rotates its token under the job row lock, and increments the same job through at most three attempts. Exhausted jobs retain native failure state. A prepared terminal request retains priority. Prepared terminal content whose lease expired before terminal commit remains a specific liveness hold under the existing exact-retry contract; this patch neither discards it nor claims universal crash recovery. Drain/admission checks do not cancel in-flight work.

The handler admits a bounded page, exposes only sanitized state, refuses request bodies, and calls each RPC once using native fetch. HTTP timeout is ambiguous; the next invocation discovers retained native state. The 45-second check is an admission cutoff, not a whole-operation ceiling. Each fetch has a15-second client abort; database or provider work may continue after that abort.

A later separately approved host installation must supply an HTTPS qik PostgREST RPC URL, publishable (or legacy anon) API key, narrowly scoped mip_comparison_worker_v1 JWT, bound unexpired native session, runtime and evaluated implementation; no administrator credential is accepted in either credential field. It must expose only the reviewed RPC schema/grants, not grant table access or publisher authority. The source-only016 compatibility delta installs after001..005 and013..015. The handler now selects mip_identity, whose four added journal/recovery wrappers perform the existing external workload mapping/key/session authorization before and after delegation to the same013 journal and015 native owner. Worker access to all direct mip_cutover_authority operations is revoked. Only the existing NOLOGIN kernel receives supporting journal SELECT and lease-owner SELECT/INSERT with role-specific RLS. No new journal, issuer, broker or queue is introduced. Hosted provider JWT and broker session handoff remain separately unqualified.

The proposed invocation is an exact opaque bearer secret in MIP_QIK_WORKER_INVOKE_TOKEN. Supabase Edge's default gateway JWT verification is not compatible with that opaque bearer. Any future installation must explicitly review and set verify_jwt=false for this candidate only, leaving application authorization in host.js, or separately review a compatible JWT invocation contract. No such configuration is applied by this source commit. index.ts reads only the named MIP_QIK_* configuration and never falls back to SUPABASE_SERVICE_ROLE_KEY.

Required hosted checks remain: actual gateway authorization and refusal, narrow JWT/session handoff and renewal, schema visibility/execute-only grants, Deno import boot, and fresh-runtime resumption. No public API activation or recurring schedule is created. Historical backfill and ongoing intake remain independently governed; output completion does not publish, release or cut over YHB.
