## Producer, persistence and actor boundary

`supabase/source-proposals/investigationSelectiveIntakeHandler.mjs` exposes `createSelectiveIntakeHandler({ authenticate, workspaceRpc, rpc, allowedOrigins })`. It uses the current verified Auth and native workspace RPC supplied by the existing gateway. It accepts only `read`, `receipt`, `declare`, and `reconsider`, with bounded JSON and explicit input fields. It never accepts request JSON actors, roles, trusted observation objects, or computed results. No transport, credential, Auth client, endpoint deployment, new Auth roundtrip, or background producer is added.

For declarations, the handler reads the exact investigation version and its native observation, verifies reviewer access, and invokes the frozen pure validator. For reconsideration, it reads the original receipt and original/current native bundles through the same assigned owner, then calls the frozen reconsideration validator. The native workspace observation is a table row; its enclosing private owner supplies `publicly_eligible:false` when constructing the validator envelope. No private snapshot is sourced from request JSON.

The canonical validator output is stored unchanged as receipt `result`. Its `provenance:caller_self_assertion`, `persisted:false`, `execution:none`, and hashes remain exactly as the pure draft produced them. The **outer** receipt reports `persisted:true`, `retention:durable_private_receipt`, exact actor/version/candidate/capture/observation/input references, and private/default-deny authority. This prevents adding a verified-actor stamp from invalidating the canonical declaration hash used during later reconsideration.

SQL's `actor_binding:assigned_reviewer_trusted_gateway_input` accurately describes its boundary: it receives the trusted service-role actor UUID and checks assignment; direct SQL does not verify an Auth token. The handler's success envelope separately stamps `authenticated_user_id` from verified Auth. Neither a receipt tag nor a hash proves historical Auth, registered criteria/policy authority, permission to acquire or display a source, or truth of the annotation. Privileged direct service-role/admin operations remain a trusted administrative boundary, as in the existing native owner; this change does not sandbox that role or claim independent authentication of arbitrary old rows.

An optional `X-MIP-Expected-User` header is nonauthoritative account-race metadata. The handler compares it only to the verified Auth ID and returns fixed `401 authentication_required` before any workspace/receipt RPC on mismatch. The client captures expected-user metadata before awaiting transport and validates the successful server Auth stamp, including reads. A historical receipt's actor may legitimately differ from the requesting assigned reader; these identities are kept separate.

## Durable database rules

`supabase/source-proposals/investigation_selective_intake_v1.sql` defines the private receipt RPC and one table, with RLS and no browser-role table/RPC grants. `service_role` receives only required receipt select/insert/sequence/helper privileges; no update/delete privileges. History mutation and truncation triggers preserve receipts.

Writes take the same per-investigation owner lock as native workspace version writes and lock membership against concurrent revocation. New receipts must target the latest native workspace head and latest per-investigation/candidate receipt predecessor. Exact retries return the original payload even after a newer head, while conflicting reuse of a receipt ID rejects. The database computes a fingerprint over the actual submitted normalized JSON, including injected actor and exact payload; the frozen validator computes its own declaration/snapshot hashes on the server. SQL rechecks native scope, capture/hash/extractor/input/version/observation links and explicit dependency/relevance records; it does not independently authenticate a caller-supplied checksum or classify relevance.

Reconsideration must reference the latest declared disposition, a native direct-successor observation for the same explicit candidate scope, and a newly observed bound stale cause or positive-relevance record. It retains the original disposition and says `needs_reconsideration`. Native corrections and new relevance alone create no selective receipt. No request dispatches analysis, changes an assessment outcome, updates a workspace review, deletes retained captures, changes rights, or makes anything public.

Input positions and receipt ordinals are emitted as decimal strings, including odd values above JavaScript's safe integer range. Ordinals order this locked private receipt chain and page its history; they are not corpus/commit freshness watermarks or evidence of search completeness.

These are **post-capture, post-candidate** selection annotations. The frozen contract requires actual retained assessment or relevance references, so it cannot represent pre-fetch selection of unknown/unretained sources. `analyze_now` declares intent; it does not mean analysis ran. `skip_for_now` retains existing immutable source history. Method key/version, policy version, domain classification references and rationale remain explicit reviewer assertions; no automatic selection threshold, prioritization, scoring, religion silo, provider authority, or registered policy approval is invented.
