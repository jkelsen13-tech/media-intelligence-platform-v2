## Evidence limits

The receipts justify capture identity and declared provenance. They do not
contain a reviewed actor identity registry or reviewed relationship assertions.
Shared actor identities therefore remain unresolved. Co-occurrence, common
investigation membership and identical actor labels create no actor merges or
substantive edges. Exactly two shared declared provenance labels are supported:
`doj-executive` (8 receipts, Epstein/Project 2025) and `us-whitehouse` (9 receipts,
Iran/Project 2025). Their 17 provenance edges retain capture, article, candidate,
hash and exact-span evidence roots; they assert neither substantive relationships
nor independent corroboration. Every source identity tuple must match a frozen
receipt before gaining such an edge. Selecting an origin opens its global
membership, allowing traversal to a source in another investigation. Global
search displays each result's investigation
membership; selecting a result outside the current lens switches to the union.
Changing to an incompatible lens clears selection rather than fabricating
membership. Comparison, chronology and geographic refusals remain explicit.

## Private hosting boundary

The presentation session is not authentication. This static artifact must be
served only behind verified hosting authentication covering HTML and every asset.
The account panel states that prerequisite; it cannot verify the host from a
network-disabled static client. No login simulation, backend client, auth token,
Supabase key or mutation transport is introduced. This change does not deploy,
configure hosting authentication, or grant access. Before any authorized Preview
is shared, verify anonymous HTML and asset requests are denied by its host.

The production entry must exclude demoCorpus, demoSession and both receipt
manifests. Existing compiled import-closure tests enforce that boundary. The
separate demo build excludes production public assets and Vite environment keys.
Its explicit brand-asset plugin emits only `assets/mip-mobius-logo.png`, matching
the native shell request while leaving `publicDir: false`. The demo account seam
uses `Private preview` and `Demo reviewer` presentation labels; the native account
button retains its existing production defaults. These labels confer no authority.
The demo entry's content security policy disallows connections. Its frame-ancestor
restriction must additionally be supplied as a hosting response header (browsers
do not enforce that directive from a meta tag).
