# Story correction lineage

A reviewed correction can make its predecessor's claim or source unavailable. Requiring that predecessor's current public payload prevented the successor's material declaration, hid the correction from Following unread state, and removed it from public material history. The corrected source uses immutable owner-admitted lineage identity for the predecessor and retains current public authorization for the successor.

`declare_public_story_material_change_v1` still requires the actual publication owner, exact same-Story admission rows, the successor's exact predecessor ID and adjacent sequence, a currently visible successor, changed exact source membership, successor evidence references, and review/policy binding. It does not read or return the predecessor's source snapshot or nested evidence. Its existing private registry lookup is the lineage authority; a public payload reader is not an admission-ledger reader.

Private unread counts, material rows and unclassified-version checks explicitly join the immutable same-Story predecessor/successor rows and authorize the successor payload. The public material-history RLS policy likewise authorizes the successor and current head, without requesting predecessor payload. Public context evidence still comes exclusively from the canonical currently authorized successor envelopes. Ordinary predecessor payload reads continue to return unavailable when source or nested claim permission is gone; current-head denial never chooses an older successor. No public owner code, new SQL function, signature, grant, schema exposure, or reviewer authority was introduced.

The new [actual SQL, gateway and SDK regression](../tests/storyFollowingCorrections.test.mjs) covers superseded claims, withdrawn predecessor sources, cross-Story and missing predecessor IDs, forbidden evidence refs and private keys, declaration refusal for anon/authenticated/service roles, denied private ledger reads, expected-actor mismatch, other-account isolation, successor withdrawal, displayed successor acknowledgement, and Source Report correction attribution. The fixture preserves the existing nested two-eligible-outlet publication gate when withdrawing the predecessor. All reviewer admissions and source records are synthetic disposable owner actions; these checks do not qualify real corpus accuracy or the synthetic News policy thresholds.

Durable revocation remains distinct from correction publication. If the successor is already admitted when its superseded predecessor withdraws, an active follow can receive that successor's unread correction. If withdrawal first revokes a follow while its old head is ineligible, a later successor declaration does not resume it. Following again requires the user's explicit choice and acknowledges the successor version actually displayed.

The unchanged exact-signature ACL and catalogue recovery tests accompany this regression. Source proposals remain unapplied. Earlier App/account journey receipts remain unchanged; the new correction receipt records the changed source and scoped reruns separately.
