## Reproduced defects and repair

1. The parser deliberately represents malformed or duplicate `subject_type` metadata as an explicit null type. App used nullish defaults both when hydrating external hashes and when choosing the selection catalog. A route naming `event-a` with invalid type metadata could therefore retain the event's actual `arc-a` and joined `entity-a` inspector, including when replacing the same currently selected event. App now distinguishes an omitted type argument from explicit null. Explicit null receives an empty catalog before graph or Markets fallback, including the catalog revalidation after cold hydration. Genuine omitted metadata still uses the existing legacy event default. Well-formed custom type metadata retains its existing semantics; no new type allowlist is introduced.
2. Cleared or invalid external hashes returned before superseding an older asynchronous article resolution. A pending article could later replace the surviving investigation and Arcs view. Every external `hashchange` now advances the existing navigation intent generation before either early return. A noncommitting route preserves current investigation state while refusing that late response. Valid current-route restoration and newer explicit article navigation continue to work. Internal `history.replaceState` serialization does not emit a hashchange.

Only `src/App.jsx` changes production behavior. The existing parser, canonical identity, precise time helpers, graph join rules and article resolver remain the owners of their respective contracts.
