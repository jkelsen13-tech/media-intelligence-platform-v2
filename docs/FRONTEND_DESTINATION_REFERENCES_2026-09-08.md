## Shared visual direction

- Light, compact desktop workspace with restrained borders, pale surfaces,
  blue selection accents, consistent typography and deliberate information density.
- Narrow left navigation with the current investigation retained across views.
- Persistent search/filter area and shared investigation header with summary,
  source-backed image when available, recorded location/time and evidence context.
- A central view-specific canvas beneath a consistent view selector.
- A right evidence inspector with provenance, exact record identity, uncertainty
  and relevant details of the selected object.
- Supporting legends, context and controls close to the visualization, with
  progressive disclosure for detailed evidence.

## Meaning and responsive behavior

The screenshots guide composition and interaction, not fabricated evidence.
Illustrative Gulf Coast events, percentages, independence counts, confidence
indicators, weather values, trend lines and status badges must not be copied
as live facts. Any such feature requires an authoritative supported contract,
provenance and clear uncertainty. Missing data stays explicit.
Existing methods/vocabulary authorities govern labels and quantitative claims.

Preserve exact saved versions and the distinction between a private observation
and current public projections. Maintain synchronized selection across Graph,
Timeline, Arcs, Source Comparison and World View.

Phones receive a deliberate responsive adaptation: accessible Account/login
control, navigation drawer, readable summary, view-specific workspace and
inspectable evidence panels. Do not shrink the full desktop dashboard onto a
phone or make tiny screenshot text the implementation target. Tablet behavior
must preserve readable content and predictable inspector access.

## Delivery sequence

Finish and verify the in-flight evidence-integrity batch. Then reconcile the
existing shell/components/tokens against these references before a UI change.
Deliver bounded frontend batches:
1. Shared shell/header/inspector hierarchy and responsive behavior.
2. Graph and Timeline composition and selection/detail interactions.
3. Arcs and Source Comparison using available trustworthy records.
4. World View composition and context using approved, bounded sources.

This sequence is a visual implementation guide, not a waiver of prerequisite
evidence work or a promise that every mockup feature already has live data.
Reuse existing components and assets with established rights. Uncertain new
assets/dependencies/sources remain held; POWER remains inactive.

Each batch requires representative built-app screenshots and interaction tests
before conditional merge, then live verification after deployment. Compare the
relevant original screenshot with the implementation at a comparable desktop
viewport, and verify phone/tablet adaptations separately. Record actual scope,
remaining gaps and data limitations; do not mark visual alignment complete
merely because the shell or one view is improved.
