# Content-addressed hot/warm/cold/deep_archive storage: staged implementation plan

## Objective and current boundary
Retain exact evidence, assessment revisions and audit history while reducing repeated bytes and letting the interface retrieve metadata before heavy content. Content identity is SHA-256 of the canonical original bytes. A summary, embedding, claim index or timeline entry can locate those bytes but can never replace them when supporting a factual assertion.

This independent qualification package starts from frozen PR166 commit 406512127399e63e117f2a8e0b089f97579bd0d9. It does not modify PR172, SQL023, hypothesis acceptance, source authority, existing journal implementations or application wiring. The owner's new storage request authorizes this separate package; it does not declare hypothesis Phase A complete.

## Slice 1: coherent synthetic PostgreSQL path
Files under supabase/qualification/content-addressed-storage implement the following:
- Immutable object identity/byte length and immutable investigation-scoped logical references with provenance, source version, acquisition time, rights and privacy references.
- One deduplicated encoded representation per canonical hash. Identity-v1 and gzip-v1 metadata include an independent encoded-byte digest. Every factual read decompresses with a 1 MiB output ceiling and checks canonical hash and length. Canonical original bytes, including whitespace/Unicode, are preserved. JSON journal values are encoded using the caller's JSON.stringify bytes; this is exact-content storage, not semantic JSON normalization.
- Mutable hot/warm/cold/deep_archive state is separate from immutable evidence identity. CAS transitions append events and cannot rewrite the canonical hash, reference, provenance or assessment. A representation shared across investigations cannot be tiered by one investigation's caller; that requires a separately designed storage custodian.
- Lightweight summary/entity/claim/timeline/vector-reference locator metadata is bounded, versioned and bound to the canonical hash. A stale hash is rejected. Even a poisoned locator cannot enter factualEvidence/get results.
- Metadata first; optional locator metadata second; canonical encoded bytes last. Cold canonical reads return explicit rehydration-required state. Current native identity and investigation access are checked on every operation.
- A finite pending/completed rehydration lifecycle with exact request replay, version binding, expiry, authorization recheck and promotion to warm. Expired-job cleanup removes operational jobs only; evidence/references/events remain.
- putOnce/get compatibility verifies a committed receipt plus exact canonical readback before acknowledgement. Existing hypothesis and temporal recorder adapters are not yet wired to this store.

## Explicit limitations of slice 1
All production, publication, deployment, rights and codec qualification flags remain false. Role mappings and permission references are synthetic fixtures. The SQL session_user mapping is valid for the native fixture only; no real Supabase/Auth principal mapping is configured. The store is not a public RPC/Edge Function.

All encoded bytes stay in one disposable PostgreSQL database: hot/warm/cold/deep_archive are lifecycle states, not actual cloud storage classes, cost or latency qualification. No buckets, credentials, remote providers, archives or migrations are activated. No project files are placed on the owner's local device.

Codec admission is separated from ordinary investigation reference binding. A distinct NOLOGIN codec-verifier capability is held only by the configured verifier service; it constructs a bounded lossless representation, decompresses it, compares exact raw bytes and verifies raw/encoded hashes and lengths before SQL admission. Ordinary gateways cannot admit gzip. Their identity codec path is checked by SQL. Reference binding requires possession of the exact canonical bytes and never accepts an arbitrary unproven object hash. Existing representation retries compare raw size, codec, encoded digest and exact encoded bytes; conflicts fail. A trigger makes representation content immutable while allowing valid tier/version transitions only. PostgreSQL still cannot independently decompress gzip: this trust is explicit in the separate, production-unqualified verifier service. A global dedup collision is assumed cryptographically infeasible, not mathematically impossible. The first representation is retained; alternate codec variants and repair are later work.

Access expiry is rechecked per operation. There is no network delivery fence or promise to retract already received bytes, no independently protected custodian and no protection against the database administrator. Cleanup has no authority to delete canonical evidence. An immutable owner-only versioned policy and separate active-policy pointer configure quotas, codec/location/tier admission and byte/page limits. The native fixture version uses 128 refs/investigation, 256 objects, 16 MiB aggregate raw bytes, 16 jobs/principal and 1 MiB per object; these are synthetic test values, not architectural maxima. Object/reference usage counters avoid repeated global count/sum queries on ingestion. JavaScript byte limits are explicit configuration bound to the database policy version, with no unknown-policy fallback. Permanently immutable canonical data can exhaust these quotas and then fails closed. Native PostgreSQL transactions model transition concurrency, not cross-provider distributed atomicity.

No inferred index/summary truth is accepted. Canonical bytes establish the retained record, not the truth of every statement in it. No release of allegations, scoring calibration or rights admission follows from storage success.

## Citation join and integrated freeze invariants
An assessment citation must carry the immutable logical reference ID, canonical hash, retained source version, exact byte offsets and the exact span hash. resolveCitation checks the reference/version/hash before bounded decompression, checks the full canonical digest, validates span bounds and then verifies the exact span digest under the current authorized read. It never searches similar passages, resolves latest source content or uses locator text as evidence. Offsets in this contract are explicitly bytes; existing hypothesis code-point offsets require an explicit checked adapter, never an implicit conversion.

The return verifies the retained span only; it does not establish claim truth. A summary, embedding, entity, claim or graph index may locate a citation but cannot qualify factual support without this exact canonical join. Cold content blocks the citation until authorized rehydration completes.

A future adapter must map each saved assessment source_span to this exact versioned citation contract, preserving the saved input/source identity and converting span units against verified canonical bytes. That adapter is not implemented here because it would cross the hypothesis/storage boundary. Native slice tests do implement the narrow citation resolution contract and prove old-version/current-version mismatch, span/hash denial and cold-blocked then exact rehydrated resolution.

Cross-layer completion requires one frozen integrated tree/commit, configuration and corresponding test evidence covering the frontend→API→authorization→canonical citation journey. Green divergent branches are component evidence only. This storage PR is deliberately independent and cannot be labeled full-platform completion.

## Four-tier scale architecture and acceptance gates

The storage model must serve millions and tens of millions of records. Retrieval/compression/indexing may improve locating content, latency and cost; they never change what counts as evidence.

The four lifecycle tiers are hot (interactive), warm (online compressed), cold (rehydration required) and deep_archive (explicit delayed rehydration). Slice 1 models all four states and refuses canonical/citation delivery from either archive state. Physical archive latency, restore requests, retention windows and providers are future adapter evidence; state labels do not establish those properties.

Canonical object IDs remain stable across tier/codec/location changes. At scale use content-hash-prefix object shards and tenant/investigation/time partitions for references and append-only events. Keep one canonical object with many domain references rather than duplicating bytes for news, evidence, markets or graphs. Every reference preserves its own source version, permission scope, provenance and retention dependencies. Physical manifests must bind object hash, codec/version, encoded digest, provider/location/generation, encryption-key reference, index references and verification state. Unknown versions, codecs, rights, locations, tiers, spans or hashes fail closed. Actual key material never appears in manifests.

The current schema has investigation/ref keyset indexes, JSON locator GIN indexes and summary full-text GIN indexes. Locator responses contain only candidate reference/hash/source-version. Array locator fields use exact membership, summary uses simple full-text tokens; vector references are exact IDs, not semantic vector search. Pagination cursors bind query/scope/page size, active policy version and investigation index generation; stale/ambiguous cursors fail. Index generation is locked during each page to prevent a concurrent publication from silently changing cursor meaning. Only returned page candidates undergo hash-binding verification; no whole-investigation validation scan is required. An index can miss evidence or contain a false statement; neither omission nor statement becomes factual support.

Before admitting scale, measure actual plans on 1M and 10M synthetic records partitioned across representative investigation distributions, including one unusually large investigation. Require bounded output, no unbounded candidate materialization, index-driven partition pruning and stable keyset traversal under concurrent index updates. Record scanned rows, buffers, sort/spill, lock wait, p50/p95/p99 latency, peak memory and cold-rehydrate throughput. A green small fixture does not pass this gate. The present global quota lock/counters are a correctness reference; scale deployment must shard counters/admission by policy scope, preserve atomic reservations and measure contention/backpressure before adoption.

Promotion/demotion should batch by shard/provider and reserve quotas/egress/rehydration budgets before work. Use per-tenant and global queue limits, worker leases, retry budgets, idempotent operation IDs, cancellation, circuit breakers and explicit pending/unavailable/expired outcomes. Never bypass a cold queue by substituting a summary. A custodian must check all referencing domains before moving/deleting a shared representation. Deep-archive SLAs/error budgets must specify maximum queue delay, provider restore delay, retention of rehydrated copies, timeout/cancellation behavior, retry count and unavailable-state UX; concrete production values await measured provider trials.

Delta plans require periodic full checkpoints, exact target digest/length, bounded chain depth/expanded bytes, independently identified base objects and verified codec/patch versions. Full reconstruction must pass hash verification before citation reads. Graph plans require periodic canonical snapshots plus append-only changes with sequence, predecessor, schema/method and source references. Replay must detect gaps, duplicate/out-of-order changes, missing checkpoints and divergent lineage. Neither plan is implemented in slice 1.

Integrity sampling must check encoded and canonical hashes by policy tier/shard, trace sample provenance, quarantine mismatches and prevent corrupted objects from evidence delivery. Sampling does not replace per-read hash verification. Record canonical/encoded byte totals, compression ratio, dedup ratio, index footprint, tier distribution, object counts, egress bytes/cost, rehydration requests/bytes/cost, cache hit rate, corruption/codec failures, queue delay, restoration latency and quota denials. Keep metrics free of source content and sensitive identifiers.

Release gates: native correctness and adversaries; separate codec/identity/custody review; remote multi-provider crash/recovery trials; 1M/10M load and economics evidence; exact citation integration; one frozen combined candidate/configuration with independent acceptance. No production scale, codec, rights, deployment or publication qualification is claimed by this package.

## Current policy and admission checks
Owner-configured source-version/rights/privacy tuples must exist and remain unexpired for reference binding and evidence reads. Fixture provenance strings alone are insufficient. Native tests use explicitly seeded synthetic tuples; real rights are unqualified. Unknown source versions or rights references fail closed.

Codec service admission can precede reference binding; a later reference conflict may leave an admitted unreferenced immutable object. Its bytes remain charged against quota. Canonical object garbage collection is intentionally absent pending a separately reviewed all-reference/retention protocol; operational job cleanup cannot erase it. First-representation fingerprint conflicts are refused rather than silently adopting different compression bytes.

The locator page checks canonical/index binding only for the bounded candidates it returns. It does not claim index completeness, semantic relevance or truth. Poisoned locator text may identify a candidate but exact citation resolution still demands the original canonical bytes and span hash.

## Configurable admission and mutation receipts
The JavaScript policy now pins nonempty unique bounded allowedLocations, allowedCodecs and allowedTiers arrays as well as numeric limits. The disposable location is a fixture configuration value, not an application constant. Reads verify database policy arrays exactly; codec decoding and tier/location handling validate configured membership.

Logical keys are validated before transport use. Bind/put receipts require exact fields, the same retained reference/hash, committed=true and production_qualified=false. Rehydration request receipts require a valid job ID and known state; transition counts must equal the requested next version; cleanup counts must be nonnegative safe integers. Void completion/index RPCs return null only and do not themselves certify evidence delivery; consumers must perform an authorized read to obtain any evidence.

Root identified invalid DO-block delimiters in the unexecuted quota tests at 17a4d0543fc4d258f9b9f55e3f5930e65863202a. They now use explicit quota tags, and each test still demands the specific quota error. Parser failures cannot satisfy the assertion.

## Policy-driven physical representation admission
The representation schema validates bounded codec/location identifiers rather than enumerating the current codec implementations or defaulting to a disposable location. Each versioned policy explicitly selects initial_location and initial_tier, constrained to its allowed arrays. The trusted admission function uses those values and includes actual location/tier in its receipt. Policies reject empty, duplicate or invalid identifier lists; the four supported tier meanings remain explicit.

A native transaction test configures a non-disposable location and a future codec identifier, admits and reads its encoded representation through separate SQL principals, then proves JavaScript refuses to decode the unimplemented codec. This demonstrates a policy-compatible schema, not qualification of that codec or provider. JavaScript only implements identity-v1/gzip-v1 and fails closed for every other codec even when SQL policy admits its identifier.

## Post-hosted adversarial reconciliation: isolated candidate, not release qualification

The original abf7afea head passed its dedicated synthetic run (34877703389, native job 104088891765, 19 tests including parent). Independent exact-read review then found untested policy/availability/source-authority boundaries. That green result is preserved as evidence for the old tests only; it does not qualify this descendant or invalidate the newly found blockers. The new native adversaries must execute on the exact descendant before any claim of closure.

Admission and reference binding remain separate transactions for the configured codec service. Bind now verifies the current policy, exact immutable object size, and stored codec/location/tier/encoded-size limits before both insertion and retry. Admission retries revalidate the existing representation against current policy before receipt. Bind holds a representation SHARE lock through reference commit; ordinary binding to cold/deep_archive is refused (including retries), while hot/warm cross-scope dedup is allowed. Rehydration of an existing unique archived reference remains available. A future custodian workflow is required for deliberately sharing unavailable archived content.

Lock order: bind/admit take current-policy SHARE then quota advisory then representation SHARE. Transition takes current-policy SHARE then representation UPDATE, checks cross-scope references, and never takes the quota advisory lock. Native two-session tests hold each winning transaction open and require the other operation to wait and fail: either hot shared content, or cold unique content, never cold shared content. Existing completed rehydration request replay must match current expected version + 1 and warm tier, just as completion replay does.

Source authority is structurally separate from caller metadata. An owner-seeded immutable source_identities row records a synthetic capture UUID, investigation, source version, canonical hash, exact raw size and acquisition timestamp. Multiple explicitly seeded captures may belong to a source version; the full hash/time identity disambiguates them. Mutable rights/privacy/expiry remain in source_permissions. Gateway bind verifies the complete identity and raw size, and every subsequent source check and locator filtering joins the same identity. The gateway cannot create capture authority from bytes or supplied labels. Corrections require new trusted capture/version records; old identity rows cannot be updated. This fixture does not connect to or qualify a real source-capture authority. Read, bind receipts, locator envelopes and exact-citation results explicitly retain source_identity_qualified=false and temporal_provenance_qualified=false.

Job admission counts only unexpired operational jobs under the per-principal advisory lock. Expired request replay remains denied while its row exists. Cleanup requires current authorization to any supplied investigation, takes that same principal lock, and deletes only the caller's expired operational jobs globally, in batches bounded by the active policy max_jobs. It returns a count, not old investigation contents. The same versioned value currently limits live jobs and cleanup batch size; production policy may separate them. Revoked prior investigations therefore cannot permanently strand quota or cleanup. Cleanup does not delete evidence, references, source identities or history. Once a request row is cleaned, its UUID may be reused as a new operational request, with fresh current authorization/version/tier checks; permanent request tombstones and retention economics remain a later design gate.

Hash-leading refs(hash,investigation), events(hash,next_version), and jobs(user_id,expires_at) indexes support cross-scope checks, history and bounded operational cleanup. Catalog tests cover the access paths, but do not claim representative planner, load or 1M/10M performance qualification. All production/publication/deployment/rights/codec/physical-tier/scale gates remain false.
