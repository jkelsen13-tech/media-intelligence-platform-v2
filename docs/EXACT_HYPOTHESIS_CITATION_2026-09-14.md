## Confirmed interface gap and explicit new contract

The parent CAS stores whole canonical bytes; `putOnce` uses JSON.stringify. A decoded JSON field containing newline/quotes is not a contiguous substring of those serialized object bytes. Existing hypothesis spans are Unicode code points into a retained field, not byte offsets into the JSON envelope. Neither matching text nor source-version labels establish the missing mapping.

This additive contract does not reinterpret those bytes. A source-only plan reads one exact retained observation/input and requires its parent CAS object to equal PostgreSQL retained-record JSONB::text UTF-8 (`postgres_retained_jsonb_text_utf8_v1`). Its material UUID must equal the parent source_version, and its acquisition time and complete retained-envelope hash must match. Other parent serialization forms deny; no implicit normalization or fallback is attempted.

The plan derives a distinct field capture UUID/source_version using SHA256 of a domain-separated PostgreSQL JSONB tuple containing contract, investigation, immutable parent ref/source-version/hash, retained material UUID, field name and exact field hash. The caller cannot provide the derived hash/version/offset. The full field's exact UTF-8 bytes are separately stored through existing CAS admission. `register_field` verifies that already-existing field object/ref/hash/size/capture/source-version/acquisition-time relationship and both current source-rights tuples. The CAS UNIQUE(investigation,source_version) invariant remains unchanged: the derived field identity is distinct and linked, never passed off as the whole source.

Source-only plan/registration is an explicit synthetic ingestion authority. Neither function admits a CAS source identity or grants rights; existing owner authority must separately seed/attest the two CAS identities and current rights. Production capture authority and extraction attestation remain unqualified. The plan intentionally returns exact field bytes only to the separate NOLOGIN source role for source-owned admission. Gateway roles cannot call it or read registry tables.

## Binding and reading

Immutable registry mapping binds investigation, retained workspace/input, material, field, parent and field refs/hashes/source identities, and declared `utf8_field_bytes_v1`, `unicode_code_points_v1` and `utf8_bytes_v1` contracts. Registration retries return the same immutable mapping only for an exact identity match; conflicting or ambiguous mappings deny. Binding takes investigation/revision/evidence/mapping identifiers plus a caller-owned request UUID. It reuses the selected saved-history current-permission checks, verifies exact evidence/input/material/field/workspace matching, derives byte bounds in PostgreSQL from the exact retained field, and verifies the saved excerpt_sha256. No caller-computed offsets/hashes are accepted. Before requesting persistent binding, the JS adapter obtains an authorized preview and independently decodes/verifies both complete canonical objects and passage. SQL binding rederives current identity/permissions again, and the receipt must exactly match the preview. Immutable CAS representation bytes prevent a legitimate byte replacement between these operations; tier/rights changes can only cause denial.

Every read rechecks current investigation authorization and selected-assessment permissions (including existing generation/reassessment closure), rederives and compares the entire immutable mapping/binding, and invokes current authorized CAS canonical reads for both parent and field. Parent or field cold/deep state denies until successful bounded existing rehydration of the exact version. No locator, index, embedding, summary, latest version or similar-passage fallback exists.

JavaScript independently verifies both complete canonical object hashes with the existing CAS decoder/pinned policy, exact refs and source versions, strict UTF-8, code-point-to-byte conversion and exact span hash. Only the passage, explicit parent/derived-field provenance and false qualification flags leave the adapter. The response is deeply frozen, with detached nested provenance snapshots; later mutation of the transport object cannot rewrite the returned identity. Exact passage verification is not claim truth.

## Bounds and limits

Retained parent and field units are each capped at 1 MiB; spans at 2,000 code points / 8,000 bytes. Each mapping JSON is bounded to 16 KiB and each binding JSON to 24 KiB; text identifiers and spans retain per-record bounds. The citation registry has no global count scan, insert mutex or permanent record-count ceiling. Primary/foreign keys lead with investigation, and indexes cover material/field and field/revision lookup, permitting a future investigation-partitioned design without changing cross-scope identity constraints. Physical partitions, tenant capacity policy, admission/backpressure and measured 1M/10M behavior require separate reviewed operational work; these keys alone do not qualify scale. There is no unbounded history scan, arbitrary content search or object garbage collection. Source plan examines the existing retained observation envelope and is not a large-source streaming parser; scale is unqualified.

The JS citation adapter has an eight-second response deadline and forwards AbortSignal, but does not claim independent cancellation of a noncooperative transport. After mutation is sent, any timeout, transport failure or invalid receipt reports exact_citation_outcome_unknown with the caller request UUID; it never implies rollback. An immutable investigation/user/request receipt provides exact idempotent replay/readback. Reuse for different arguments denies, and every retry rechecks current authorization and identity. Per-request serialization is scoped to that investigation/user/request, not a global registry lock. Receipt keys and lookup indexes remain investigation-leading and per-record bounded. Native disposable transport/query limits remain existing fixture constraints. Database permission locks hold during the native read transaction; post-transaction delivery/custody is not a production transport admission. No source, ingest, rights, codec, temporal, production, deployment or publication qualification is granted.
