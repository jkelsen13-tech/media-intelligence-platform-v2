# Legacy atomic completion source repair — 2026-10-02

The actual `backfill-legacy` extraction path now gathers pure heuristic proposals and calls one atomic private completion RPC. It issues no article source patch, canonical entity resolution, alias/count mutation, citation replacement, extraction marker update, or provider call. Missing installation and rejected completion fail closed. Existing private eligibility is preserved: only rows with no legacy extraction marker and either a non-eligible reader state or a non-active source status enter this private pass; run tags remain exact.

Selection returns the latest native record-version UUID and an SQL-authoritative source snapshot hash. Completion locks the article, rechecks private eligibility, compares both the selected version and snapshot hash, validates a bounded proposal, and retains the exact raw publisher fields as a native `article_captures` record together with an append-only private completion. All work occurs in one database transaction. Existing exact raw captures are reused; an unfinished conflicting native capture job causes denial and must be reconciled by its existing owner. The function does not claim unrelated native jobs, refresh leases, resolve ambiguous URLs, or overwrite source bytes. A source revision produces a new native record version and becomes discoverable again.

Private normalization, claims, entities, citations, and digest suggestions remain untrusted proposals. A completion has `publication='withheld'`. It does not create an admitted claim, update an article extraction marker, change capture review state, or make subsequent graph/origination work eligible. Metadata-only reference bodies retain empty relation proposals and preserve existing shared rows. Historical `entities_extracted_at` and graph pass behavior outside this bounded extraction repair are unchanged; this source package does not reactivate them. The old corpus marker count can include privately completed records and is not a private completion count.

A distinct owner-only `mip_legacy_reviewed_completion_v1(uuid,uuid,text,uuid,jsonb)` can replace explicitly reviewed article entity links and citations. It first invokes the existing `mip_private.require_reviewed_public_article_version(uuid,uuid,text)` lock helper. The newest visible admission must be a reviewed proposition bound to the exact same article, native capture, and hash as the private completion. Each accepted link/citation must name an already admitted article-claim evidence row and literal surface in that exact excerpt. Entity identities must already exist; the RPC cannot invent an entity, alias, mention count, claim, event, source admission, or source patch. Validation, derived replacement, and the reviewed completion receipt share one transaction. Neither the ingestion service nor readers receive execution rights for this owner-only function.

The new NOLOGIN, NOINHERIT, NOSUPERUSER, NOBYPASSRLS, NOCREATEROLE, NOCREATEDB, NOREPLICATION role `mip_legacy_completion_owner` owns only the fixed private definer function. PostgreSQL requires an UPDATE privilege on at least one article column for `SELECT FOR UPDATE`; this proposal grants only `UPDATE(id)` to the dedicated role. The native immutable identity trigger rejects actual ID changes, and the function has no article UPDATE statement. Its explicit RLS policies restrict source access/locking to the same private predicate. The service has no SET/INHERIT/ADMIN membership in this role and receives no general article UPDATE. Canonical entity and shared derived table mutation privileges are absent from the dedicated role.

The existing `qik_ingest_fn_owner` was not reused because this source qualification does not establish that its unrelated privileges and inheritance boundary are narrow enough. The dedicated role introduces an explicit new installation authority that must be separately reviewed. Schema CREATE is granted only during function ownership transfer and revoked before commit. All new function ACL edits use exact signatures; no existing function or view is replaced, and unrelated overload ownership/ACLs remain unchanged.
