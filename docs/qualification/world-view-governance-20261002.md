## Integration contract

Create `createWorldViewResourceGovernance({now,idleSuspendMs,idleDisposeMs})` with a monotonic millisecond clock. Call methods on the returned object. `openSession` records a product session; `interact({locationKey})` records an interaction/location and resets idle; `transition` accepts visible-active, visible-idle, hidden. Neither visibility nor interactions activate paid resources. `poll` drives idle suspension/disposal. Caller drains effects and actually suspends/disposes/cancels resources, including background work. No timer, network service or resource disposal is implemented by this pure adapter.

`setAuthority` accepts an expiring snapshot: admission, entitlement, explicit spendingAuthorized, monthlyExternalSpentUsd, monthlyExternalReservedUsd, and authoritative account/global remaining USD, provider remaining quota units and concurrency remaining slots. An authenticated backend must validate identity/entitlement, atomically reserve account/global/provider/concurrency capacity and issue a unique reservation token BEFORE any provider call. `reserveRequest({id,estimateUsd,quotaUnits,concurrencySlots,authorityReservationId})` adds local pending capacity and returns allowed/reason; caller must honor it and use the genuine backend token. Strings and booleans here cannot prove server truth. Cross-tab/account enforcement is expressly not implemented.

Snapshots use the same clock domain as expiresAt. Remaining allowances and monthlyExternalReservedUsd exclude local tokens tracked by this adapter, otherwise they would double-count. The authoritative service must define this snapshot baseline and provide reconciledReservationIds only after its fresh ledger includes those settled usages. Local consumed shadows stay until that explicit reconciliation; stale allowances cannot be reused. The service must reject token replay itself. Token IDs are never recycled in a bounded adapter lifetime.

Estimates must be finite bounded upper estimates including unknown charges, never guesses presented as observations. `settleRequest` retains actual transferBytes/billableUnits/costUsd as null when unknown; conservative consumed capacity is max(reserved estimate, actual observed units/cost). Unknown cost/unit observations retain their reserved upper bounds until authoritative reconciliation. Provider overestimates can still consume more than originally reserved: server metering/reconciliation must enforce its ledger; the adapter cannot retroactively prevent that charge. `cancelRequest` is only valid after actual cancellation/release confirmation, not a way to erase in-flight charges. Late receipts remain accepted after disposal. Disposal does not release unresolved pending reservations automatically.

## Lifecycle and accounting

Defaults suspend at 30 seconds idle and dispose after five minutes. Hidden transitions suspend immediately. Resuming requires fresh admission, not automatic resource activation. Snapshot distinguishes product sessions, visible/exploration/high-fidelity minutes, interactions, locations and local active resource milliseconds from explicit provider requests, bytes, billable units and observed cost. Resource milliseconds are local active duration, not provider billing. Unknown CORS transfer is not free traffic. Location retention overflow reports unknown total rather than an invented exact count. Session request/token tracking and receipt/location retention are bounded; exhausted request capacity fails closed and requires a new adapter only after backend reconciliation.

External monthly preferences are $100 preferred/$200 hard, excluding Supabase; these are NOT payment authorization. Above the preferred threshold returns a flag; above hard ceiling refuses admission. Missing authority/source rights/entitlement/spending approval/estimates or capacity returns cheap fallback. No provider pricing, paid activation, credentials, entitlement service or global ledger is introduced.
