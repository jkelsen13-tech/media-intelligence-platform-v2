`scripts/qualification/backend-rollback-sql/boundary.mjs` loads the checked-in templates, verifies the frozen sources, and returns one-statement submissions and their source-byte hashes. It has no database driver, connect method, credential input or network API. `deriveMinimalAuthorityPlan(publicSnapshot, privateBooleanInspection)` copies inert data, rejects accessors/cycles, freezes its retained baseline, and always returns `liveReady:false`. The caller's JSON is not trusted evidence or authorization.

The public `snapshotPublic` SELECT reads enumerated catalog metadata: identities, deadlines, relevant role flags, transitive membership and grantor dependencies, all corresponding grantor/options rows, raw relation and column ACL arrays, owner/RLS/policies, schema ACLs, relevant publications, effective privileges, logging settings, CA path, and dblink signature/owner/ACL flags. NULL ACLs stay JSON null; an empty ACL stays an empty array. Its `config_present` fields are limited metadata; a public comparison cannot establish exact nonnull configuration or function-definition equality. `inspectRowsPublic` reads boolean-id counts only and does not read the stored URI. None of these templates has been executed against the managed project by this worker.

Three captures require a separately approved private executor lane and established logging/redaction protections: `inspectRowsPrivateBooleans` reads source/non-null and installed-state guards and outputs counts/booleans; `captureRowsPrivate` retains every row's exact URI in private memory outside the transaction; `captureSecurityPrivate` retains exact relevant role configuration arrays and dblink configuration/function definitions together with the public snapshot. Configuration and function bodies may themselves contain secrets. Do not route these through ordinary MCP, stdout, general receipts, serialized driver errors, or secret-derived public fingerprints. The root's authorized observations intentionally read no URI value, fingerprint or nullness. Boolean-only output does not itself authorize a secret-dependent observation.

The planner supports precisely the freshly observed missing-column-UPDATE/missing-owner-SET branch. It requires authenticated postgres NOSUPERUSER/BYPASSRLS; owner NOSUPERUSER/NOBYPASSRLS/NOLOGIN; ENABLE/FORCE RLS; exactly two columns, id boolean NOT NULL and connection_string text NOT NULL; sufficient existing SELECT/schema USAGE/dblink EXECUTE; no UPDATE(id), whole-table UPDATE or effective UPDATE(connection_string); and no existing owner-SET/owner-USAGE. The owner membership granted by supabase_admin must be ADMIN=true/INHERIT=false/SET=false, and an owner membership granted by postgres must be absent. Existing SET memberships for other roles and every unrelated grant are retained. CREATEROLE does not trigger an extra grant. The exact text,text dblink overload must be an invoker, strict, ordinary function returning SETOF record. Unknown baseline shapes are refusal, not a request to invent authority.

The fixed authority statements introduce only owner-role membership granted by postgres with ADMIN=false/INHERIT=false/SET=true, SET LOCAL ROLE owner, and owner-granted UPDATE(connection_string) to postgres without grant option. RESET ROLE returns to postgres with existing BYPASSRLS. Each deadline SET must complete as its own command before submitting the unchanged DO. Cleanup revokes only the introduced owner-granted column UPDATE using RESTRICT, resets role, and revokes only the introduced postgres-granted owner membership using RESTRICT. There is no SELECT grant, broad grant, schema DDL, feature/extension installation, role flag change, catalog write or COMMIT in the operation templates. Test bootstrap DDL exists only inside the disposable fixture.

`compareRowsPrivate` binds retained private rows, approved CA path and an explicit transform phase. It returns booleans for input validity, source validity, exact one selected row, exact expected full-row equality, unrelated-row equality and opaque credential equality. It reconstructs only the selected true row using the frozen component transform. Missing/extra/changed false rows, credential changes, NULL inputs and stale data are refusal. No row or derived URI is returned.

`compareSecurityPrivate` compares the complete enumerated private security snapshot and emits only booleans. Phase `restored` excludes only transaction-local deadline settings; phase `rollback` compares every captured field, including deadlines and role setting. The public `compareSecurity` has the same phase semantics but its explicitly limited catalog scope. The exact private comparison detects nonnull-to-nonnull role configuration, dblink configuration and body drift that the public presence booleans cannot detect. Compare the private capture's public portion with the public planning snapshot before granting authority, and bind both to the approved maintenance window. Freshness across separate statements and external concurrent catalog changes require the genuine client/provider concurrency controls; this package supplies no such evidence.

Exact pre-ROLLBACK raw ACL equality is a checked condition, not a promise of PostgreSQL GRANT/REVOKE normalization. If a legitimate NULL baseline becomes `{}` after removal, exact restoration is false even when UPDATE is denied; abort the success path and perform mandatory ROLLBACK. Never patch system catalogs or discard legitimate ACL entries to force equality. Require the exact full row/security baseline after ROLLBACK and independent verification before claiming rehearsal success. Cleanup in an aborted transaction cannot replace ROLLBACK. Grants performed in a separately committed transaction are outside this rollback guarantee and need a revised provider-approved cleanup plan.

The NULL fixture explicitly removes its own NOT NULL constraint: the unchanged DO's three-valued source-shape IF can then reach the dummy dblink probe with NULL. A raising NULL stub produces fixed probe_refused; a permissive NULL stub reaches the CAS and produces ROW_COUNT0/write_refused. No write succeeds. This is PGlite SQL-semantics qualification, not native PostgreSQL 17, libpq, TLS, dblink transport, driver cancellation/drain/disconnection, server-log redaction or multi-session concurrency qualification. The stale-value case mutates dummy data at the probe boundary in the same backend; it does not prove a real independent-session race. Native PG17 remains unavailable after the recorded archive/checksum 403 and Docker limits; no retry or bypass was attempted. The historical native PG17 24-case corpus was not reexecuted. Fresh native17/client/provider qualification, exact-source review, secure evidence custody, precise provider authority approval, and separately explicit bounded live ROLLBACK-only authorization remain required.

The membership/grantor design follows PostgreSQL 17 [GRANT](https://www.postgresql.org/docs/17/sql-grant.html) and [REVOKE](https://www.postgresql.org/docs/17/sql-revoke.html): role options are explicit and cleanup selects its own grantor. The owner/postgres execution split follows [row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html): FORCE subjects an ordinary owner to RLS, while existing BYPASSRLS belongs to the intended authenticated executor.
