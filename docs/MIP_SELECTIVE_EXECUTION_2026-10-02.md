## Policy and authority

`selective_criteria_versions` stores an immutable key/version, policy version, explicit acceptance reference and constrained `selective-metadata-rules-1` rules. Ordinary service producers can read the registry but cannot insert accepted policy or authorizations. Installation creates an empty registry. The reviewable registration template intentionally has a null acceptance reference and cannot satisfy the table constraint until a real authorized reference is supplied.

The deterministic policy first recognizes explicit scope, primary-document, public-safety, institutional-accountability, economy, correction and new-relevant-input signals. These produce `analyze_now`. Routine sports/entertainment items with no such signal produce `skip_for_now`. Mixed domains and unknown context produce `retain_deferred`. Religion/religious-institution metadata without sufficient context is retained for shared-stack reconsideration; explicit scope qualifies it for analysis. Important sports or entertainment reporting remains eligible under the same signals. Domain classifications and signals are explicit trusted operator/discovery metadata with retained classification references; keyword co-occurrence is never promoted into identity or relevance proof.

There are no probability, age, recency or numerical priority thresholds. The ten-case synthetic disposition matrix qualifies these rules, including religion/institution and sports/entertainment exceptions. It is a deterministic regression benchmark, not representative corpus calibration or evidence of extraction quality. Registry versions do not silently change historical decisions. A successor version requires a new accepted row, source authorization and discovery receipt with the exact previous-selection CAS. Original decisions remain readable.

`selective_source_authorizations` records an exact HTTPS endpoint, assigned investigation/actor, criteria version, `mip_article_json_v1` format, operation-specific rights reference, acquire/retain/analyze booleans, explicit enablement, expiry, byte/request budgets and zero incremental cost. Defaults deny each operation. Rows are immutable. An administrator may append `selective_authorization_revocations` without rewriting the old rights record. Registry, source research, public metadata and an `analyze_now` decision alone grant no acquisition permission or public-display rights.

The operator uses the existing fixed backend/service credential boundary, whose actor UUID is a trusted assigned execution principal rather than a new verified browser Auth claim. SQL checks and locks the existing reviewer membership, and the same investigation advisory lock serializes native head checks. Browser roles have no table or RPC grants. No public route, service key in `src`, SECURITY DEFINER function or Auth metadata authorization is introduced. Privileged operator/admin access remains the existing trusted boundary, not a claimed sandbox against that role.

## Execution and retained owners

`runSelectiveSource` snapshots its command, validates the exact public HTTPS endpoint, and calls SQL selection first. Skip/defer receipts retain metadata and perform zero source HTTP, capture, candidate or analysis work. Analyze-now requests obtain a one-use `selective_fetch_permits` row only after SQL rechecks the current selection/native workspace head, reviewer membership, source enablement, exact operation rights, expiry/revocation and request quota under lock. Repeated or stale permits fail closed. A grant cannot charge incremental provider cost.

The source request uses GET, redirect refusal, no request credential, a 15-second abort/deadline and streamed maximum bytes (including responses without Content-Length). URL credentials, fragments, ports, IP hosts and local/reserved hostnames reject before any backend/source request. Exact administrator-approved hostname authorization remains necessary; this is not a DNS-rebinding sandbox. The adapter currently supports the explicit JSON article contract, not arbitrary publisher HTML/RSS extraction. A different format requires a qualified adapter and exact operation authorization before activation.

`capture` rechecks retention/analysis rights, permit, returned article URL and the native head. It enqueues/deduplicates through `evidence_pipeline.enqueue`, claims that exact existing import job using the same job lease/event fields, and finishes through `finish_job`. It never claims unrelated queue work or creates another evidence queue. The native import receipt binds the selection to its exact delivered capture. A changed existing article creates a pending new capture; the original article payload/reader state is preserved. The selective owner has no publication operation.

Analysis extracts a bounded exact attributed span using Unicode code-point offsets, appends the existing pending candidate and runs the existing native assessment context/dependency owner under `selective-exact-span-baseline/1`. Its assessment is explicitly `insufficient_evidence`. This executes source extraction and dependency analysis; it does not establish truth, entailment, canonical identity, independent corroboration or semantic review. The existing investigation version retains the explicit shared scope and state. `annotate` atomically validates criteria/version/domain/disposition, selection-to-capture linkage, actual private baseline assessment and exact native receipt/head CAS, calls the unchanged post-capture declaration owner, and links its result in `selective_execution_receipts`.

The original hashed inner result remains `caller_self_assertion`, `execution:none`, `persisted:false` under its historical contract. The existing durable outer annotation remains unchanged. The new outer execution receipt is the authoritative registration/actual baseline-analysis linkage; no hash or new tag is represented as source rights, semantic proof or publication. Positions and receipt ordinals are decimal strings, including values beyond JavaScript's safe integer range.

## Automatic reconsideration

`runSelectiveReconsideration` takes only the assigned selection owner identity. It loads the existing registered declaration, its immutable baseline and the current native workspace. It refreshes through the native observation owner and chooses the earliest exact newly observed eligible cause, using bigint positions and deterministic tie ordering. A dependency change must share the original dependency's canonical subject; a newly relevant input must have an actual candidate-to-retained-input relevance declaration absent from the baseline. Arrival, a queue completion, TTL or global watermark alone does not trigger reconsideration.

The SQL wrapper rechecks reviewer/rights/execution-head authority and delegates to the existing reconsideration receipt owner, which retains the original declaration/disposition/history. Registered correction/new-relevance signals then recompute a versioned decision. The runner appends a private native assessment successor, observes a fresh native version and appends a new registered declaration with rebased dependencies. Successive corrections and new relevance are therefore handled without source refetch or rewriting the original capture/candidate. Changing investigation scope or skipping native observation lineage fails closed and requires reconciliation through the existing scope owner; retained ancestor candidates never gain declaration scope.

Each canonical write is atomic at its owner boundary. The complete network/capture/assessment/workspace sequence is not one transaction. Lost responses or a concurrent revocation/head change can retain partial private work while the execution remains incomplete. A consumed acquisition permit is never reopened or automatically refetched. Preserve the selection/native job state and reconcile through the same owners before issuing a separately authorized successor acquisition. Exact completed retries return the recorded execution with zero source requests; historical receipt retries remain idempotent after later heads. No live background scheduler is enabled by these callable automatic routines.
