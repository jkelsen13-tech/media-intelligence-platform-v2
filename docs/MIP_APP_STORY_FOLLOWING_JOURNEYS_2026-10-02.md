# App, account, and public Story journeys

This qualification mounts the production App, authentication hooks, account sheet, NewsView, NewsStoryReader, Story Following controls and Following list. The bound Supabase SDK calls the actual fixed-route investigation gateway, which verifies the fixture bearer and stamps its actor before running the actual SQL Following RPC. Public Story context and directory reads use the actual SDK, anonymous SQL read functions, and production normalizers. The disposable database installs the restored foundation and the exact reviewed-public-version and Following proposals. No hosted account, reviewer approval, external delivery, installation, or deployment is created by this test.

These journeys found and fixed two integration failures: the context RPC unnecessarily denied authorized history when a newer head withdrew, and the reader retained a withdrawn displayed source after a verified private revocation. The context RPC now delegates exact-version admission to the canonical owner. The coordinated News change withholds a stale public body and rechecks its exact owner while retaining the same private Following controller.

Graph, World, Inspector, chrome and unrelated private investigation renderers are controlled probes. Their production App callbacks and context transitions execute; their pixels and underlying evidence loaders are not qualified here. Unrelated feed loaders return empty controlled results. Authentication event delivery, initial-session completion and logout are controlled locally, while production hooks decide which session can render and when expiry removes it. The qualification artifact records the source hashes and two Node runtime results.

The new [mounted journeys](../tests/appStoryFollowingJourneys.test.mjs) establish:

- An auth event takes priority over a slower initial session response, and App binds the private read to the event's actor.
- A reviewed Story URL retains its exact historical public version while preserving the prior graph subject, Inspector selection, microsecond inspection instant and time range.
- Historical acknowledgement submits the displayed version even when the admitted head contains a later unread material declaration.
- World and Inspector return retain the Story version. A dismissed Inspector stays dismissed, Back clears the Story route, and opening a native Following result selects the exact admitted head.
- The native Following list drops a held account A response after App switches to account B, then reloads A's actual unread count only when A re-enters.
- A late unsubscribe response cannot paint account A's private state into account B. The real account sheet logout invokes signOut and removes private Following controls.
- A held private read is discarded across logout and same-account re-entry. Production session expiry removes authenticated actions.
- A held public Story response cannot replace a subsequently selected historical version. A nonexistent version withholds source data and acknowledgement controls.
- Token B while App owns A is refused before SQL mutation; this clears personal state without withholding an independently admitted public Story.
- A foreground confirmed withdrawal clears private updates and rechecks the displayed public version before retaining its source content or actions.
- Withdrawing a member present only in the newest Story revokes the private follow, while an explicitly selected historical version remains readable only if its exact members still pass the canonical public predicate. The context RPC delegates this decision to that owner; its default read still selects the newest sequence and never falls back.
- Browser storage contains no account ID, Story ID, public version ID, subscription state, or unread updates from these journeys.

The existing standalone SQL, gateway, SDK and controls qualification remains the evidence for detailed ACL, expected-catalog, revocation, CAS and bound-request cases. This package adds cross-surface behavior rather than replacing that evidence. Physical browser accessibility, hosted Auth callback delivery and live installation are separate gates; the parent task owns the final browser pass.
